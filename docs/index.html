GitHub snapshotPin the review target

Choose a source and scope

Preflight, authentication & provider limitsBefore running

setup-agents installs lockfile-pinned ACP adapters. Existing official CLI logins stay in place. The host CLIs are trusted processes; their credentials do not enter the target sandbox.

check-agents checks availability. check-agents --live makes real provider requests against an inert fixture to qualify access, saved-session recovery and submission. It does not establish security coverage or clear a policy refusal.

--blocked records an offline blocked run. Refusals, quotas and authentication failures remain explicit. The coordinator does not switch models, providers or billing routes to retry a refusal.

03How the review runs

One disposable sandbox
  1. 01 / Capture

    Seal the source

    Save bytes, omissions, hashes and existing test entry points.

  2. 02 / Prepare

    Collect static leads

    Inspect source and lockfiles with trusted scanners.

  3. 03 / Disconnect

    Verify offline access

    Remove proxy access before tests and reviewer handoff.

  4. 04 / Review

    Inspect in parallel

    Queue surfaces per provider; serialize shared test runs.

  5. 05 / Commit

    Cross-check & render

    Validate saved findings and peer verdicts, then release resources.

HostPersistent ACP sessions→Restricted MCP bridge→Offline DockerCaptured source & existing tests
Execution order & trust boundariesTechnical detail

Networked preparation runs trusted static scanners and the lead harness. It skips target builds, target install scripts, lifecycle hooks, target tests, web servers and active service scans. A trusted manifest-only preparer may fetch locked crates.io dependencies without target execution; it refuses target Cargo configuration, custom registries and Git dependencies. After network disconnection, the coordinator attempts the frozen catalog of existing tests before assigning surface reviews.

Providers run in parallel, with one active assignment per provider and the remaining surfaces queued. Faster providers advance their own queue. All surface reviews settle before peer cross-checks start together. All active sessions settle before cleanup, including after cancellation or failure.

The container runs as uid 10001 with capabilities dropped and privilege escalation disabled. It receives no host home, provider credentials or Docker socket. Source, peer claims, repository instructions and scanner leads are untrusted data.

Named credentials, environment files, symlinks, hardlinks, dependencies, generated output and review history are excluded from the snapshot. Filename filtering cannot prove that ordinary source contains no secrets. Omissions remain recorded.

Preparation is bounded; the held review has no reasoning deadline. Completion or cancellation removes owned resources. Docker daemon availability is required to verify cleanup.

Fixed test commands & shared lock5 min wait / 90 s run
npm --offline --ignore-scripts run test
cargo test --locked --offline
bash --noprofile --norc ./test.sh

The bridge reconstructs the command from the source-bound catalog. It accepts no caller-supplied executable, arguments, code, path, environment or URL. It verifies network disconnection and the captured entry-point manifest hash before execution. npm pre/post hooks are suppressed.

Shared sandbox tests run one at a time. Lock acquisition waits up to five minutes; execution then has a separate 90-second process-group limit. Missing dependencies, failed builds, unsupported runners and timeouts are coverage gaps.

A crashed bridge’s lock is never stolen: its Docker test may still be running. A new review or resume into a new output directory creates a fresh sandbox and lock. Existing tests remain untrusted target code; their output does not independently prove a finding.

06Sessions & recovery

Keep the original state
Persistent sessions

No reasoning deadline

A 30-second heartbeat records activity. One unexpected transport loss may reload the exact session when supported.

Exact bindings

Resume the same review

Workflow, source digest, models, reviewers and assignments must match. Preserve every original session directory.

Resume command & stopping conditionsNo fallback reviewers
./bin/audit run --repo /path/to/repo --agents claude,codex --surface s4 \
  --resume-from /path/to/previous-review --out /path/to/new-review

Successful immutable submissions are reused without calling the provider again. Failed assignments retain their original sessions; changed peer claims require new cross-checks. Runtime test and scanner evidence is collected again. A fresh bridge points at a recreated sandbox while retaining the original native conversation. Resuming an already resumed review still requires the original session directories. Older adversarial workflows cannot resume into this workflow.

Provider refusals, quota limits, authentication failures and malformed protocol errors never trigger automatic retries or model changes. Heartbeats cannot override provider limits. Cancellation retains committed evidence and recovery state; failed or missing outputs remain incomplete.

07Read the report

Claims → fixes → evidence
Overview

Start with coverage

Read the incomplete status, severity totals and surface map. Zero claims on an unfinished surface is a gap.

Findings

Expand what matters

Filter by severity or surface, search files and fixes, then open impact and remediation. Full source analysis and peer reviews sit one level deeper.

By model

Compare raw output

Counts precede deduplication. Critical is grouped with high. Model output counts do not measure reviewer quality.

High severityMedium / gapsLow / infoReported controls / fixes / agreement
Evidence, completeness & limitationsRead before acting

Output validation, executed coverage and security acceptance are separate. A valid model report is not a reproduced vulnerability. A passing test or scan does not certify the project or accept residual risks.

Findings require relative file:line citations, impact, preconditions, source analysis, validation limits and a recommended fix. Reported controls require evidence. Canonical MCP submissions supply findings; terminal prose does not.

Missing, failed or invalid output remains incomplete, including a reviewer that submits and then exits unsuccessfully. Source-bound test evidence and structured scanner coverage are checked separately; missing or unsupported evidence is a coverage gap. Scanner results and test counts are tool-reported, not authenticated proof.

Peer reviewers return upheld, partial or refuted with reasons and citations. Agreement remains unverified model agreement. Priority scores are heuristic, not probabilities. Green labels describe reported controls, proposed fixes or matching claims; they never certify safety.

The captured source does not establish private-source coverage, deployed-byte parity, production configuration or live behavior. Served-model/provider identity is unverified. Host CLIs and their authentication stores remain trusted.
